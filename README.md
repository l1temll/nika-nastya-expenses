# Ника и Настя — общий журнал расходов

Лёгкий PWA-журнал совместных расходов для двух человек. Проект сделан на обычных HTML, CSS и JavaScript: без React, npm, сборщика и серверного приложения. Его можно загрузить в корень GitHub-репозитория и опубликовать через GitHub Pages.

## Что уже есть

- Две вкладки: **Траты** и **Расчёты**.
- Быстрое добавление, редактирование и удаление расходов.
- Частичная оплата покупок: полная стоимость, первый взнос, остаток и несколько последующих платежей.
- История платежей по каждой покупке; каждый платёж может быть внесён Никой или Настей.
- В расчёте долга учитываются только фактически внесённые платежи, неоплаченный остаток не добавляется в баланс.
- Плательщик: Ника или Настя.
- Категории: еда, покупки, кафе, транспорт, дом, аптека, досуг и другое.
- Напоминание об оплате квартиры 15-го числа.
- Расчёт доли каждой 50/50 и суммы взаимного перевода.
- Кнопка «Рассчитались»: закрывает текущий период, но сохраняет историю расходов.
- Светлая и тёмная темы с переключателем в шапке и в настройках.
- Карточка оплаты в стиле банковской карты с прогрессом погашения и остатком.
- Адаптация под узкий экран, iOS safe areas и нижнюю навигацию.
- PWA manifest и Service Worker для кэширования оболочки приложения.
- Локальный режим на `localStorage` и необязательная синхронизация между двумя аккаунтами через Firebase.

> Важно: пока Firebase не настроен, данные сохраняются только в браузере текущего устройства. Для общей синхронизации между телефонами выполните раздел «Настройка Firebase» ниже.

## 1. Публикация на GitHub Pages

1. Создайте **новый отдельный репозиторий** на GitHub, например `nika-nastya-expenses`. Не загружайте эти файлы поверх существующего `diary`, чтобы не затронуть дневник.
2. В новом репозитории нажмите **Add file → Upload files**.
3. Перетащите содержимое этой папки. Важно: `index.html` должен лежать непосредственно в корне репозитория, а не внутри дополнительной вложенной папки.
4. Нажмите **Commit changes**.
5. Откройте **Settings → Pages**.
6. В блоке **Build and deployment** выберите **Deploy from a branch**.
7. В поле Branch выберите `main`, в папке — `/ (root)`, затем нажмите **Save**.
8. Дождитесь публикации и откройте адрес, показанный в разделе Pages. Для репозитория `nika-nastya-expenses` у аккаунта `l1temll` ожидаемый адрес будет:

   `https://l1temll.github.io/nika-nastya-expenses/`

После каждого `Commit changes` GitHub Pages автоматически публикует обновлённые файлы. Первую публикацию и обновление иногда нужно подождать несколько минут.

## 2. Первый запуск без Firebase

Можно сразу открыть опубликованный сайт. Он работает в локальном режиме:

- расходы добавляются и редактируются;
- баланс рассчитывается;
- данные сохраняются в `localStorage` этого браузера.

Но локальный режим **не синхронизирует** данные между телефоном Ники и телефоном Насти. Для этого настройте Firebase.

## 2.1. Покупки с оплатой частями

При добавлении покупки укажите полную стоимость и сумму, которую вносите сейчас. Например, при стоимости 2 000 ₽ можно внести 500 ₽ — на карточке покупки отобразятся оплаченные 500 ₽ и остаток 1 500 ₽. Позднее откройте эту покупку в списке, укажите следующий взнос и выберите, кто его вносит. Приложение сохранит историю всех платежей.

В общий баланс попадают только фактически внесённые суммы. Неоплаченный остаток не считается деньгами, которые одна из вас уже потратила. Старые записи без истории платежей автоматически считаются полностью оплаченными.

## 3. Настройка Firebase для общей синхронизации

Используйте отдельный Firebase-проект для журнала расходов. Не вставляйте в него конфигурацию от другого приложения без отдельного решения.

### Шаг 3.1. Создайте проект и Web App

1. Откройте [Firebase Console](https://console.firebase.google.com/).
2. Создайте новый проект, например `nika-nastya-expenses`.
3. Внутри проекта нажмите добавление приложения **Web** (`</>`).
4. Назовите приложение, например `expenses-pwa`.
5. После регистрации Firebase покажет `firebaseConfig` с полями `apiKey`, `authDomain`, `projectId`, `appId`.

### Шаг 3.2. Включите вход по электронной почте

1. В Firebase откройте **Build → Authentication**.
2. Нажмите **Get started**, если это первый запуск.
3. В **Sign-in method** включите **Email/Password**.
4. В разделе **Users** создайте два аккаунта: один для Ники, второй для Насти. Задайте каждой свой адрес электронной почты и пароль.
5. Не записывайте пароли в код, README или GitHub. Каждая вводит пароль в окне входа самого приложения.

Приложение использует уже созданные аккаунты. Самостоятельной регистрации в интерфейсе нет: это не позволяет случайным посетителям создавать доступ.

### Шаг 3.3. Создайте Firestore Database

1. Откройте **Build → Firestore Database**.
2. Нажмите **Create database**.
3. Выберите production mode.
4. Выберите регион базы. Регион после создания изменить нельзя; выберите подходящий вам и учитывайте требования к хранению данных.
5. Завершите создание базы.

### Шаг 3.4. Ограничьте доступ ровно двумя аккаунтами

1. Откройте файл `firestore.rules` из этого проекта.
2. Замените `NIKA_EMAIL@example.com` и `NASTYA_EMAIL@example.com` на реальные адреса двух созданных Firebase-пользователей.
3. Скопируйте весь текст `firestore.rules`.
4. В Firebase Console откройте **Firestore Database → Rules**.
5. Замените правила в редакторе скопированным текстом и нажмите **Publish**.

Правила разрешают чтение и запись только после входа и только двум адресам из списка. Не публикуйте базу с открытыми правилами `allow read, write: if true`.

### Шаг 3.5. Вставьте конфигурацию в app.js

Откройте `app.js` и в самом начале найдите:

```js
const FIREBASE_CONFIG = {
  apiKey: "PASTE_FIREBASE_API_KEY",
  authDomain: "PASTE_PROJECT_ID.firebaseapp.com",
  projectId: "PASTE_PROJECT_ID",
  appId: "PASTE_FIREBASE_APP_ID"
};
```

Замените значения на соответствующие значения из Firebase Web App config. Например, структура будет такой (значения здесь демонстрационные):

```js
const FIREBASE_CONFIG = {
  apiKey: "ваш-api-key-из-firebase",
  authDomain: "имя-проекта.firebaseapp.com",
  projectId: "имя-проекта",
  appId: "ваш-app-id"
};
```

Сохраните `app.js` и загрузите обновлённый файл в GitHub через **Add file → Upload files** либо откройте файл и воспользуйтесь кнопкой редактирования. Подтвердите `Commit changes`.

Firebase Web API key в клиентском приложении не является паролем базы. Защита данных обеспечивается Authentication и Firestore Security Rules. Никогда не помещайте в `app.js` пароли пользователей или приватные серверные ключи.

### Шаг 3.6. Войдите с двух телефонов

1. Откройте опубликованную страницу на телефоне Ники.
2. Нажмите значок настроек в правом верхнем углу.
3. Введите почту и пароль аккаунта Ники и нажмите **Подключиться**.
4. На телефоне Насти откройте ту же ссылку и войдите под аккаунтом Насти.
5. Добавьте тестовый расход на одном телефоне. После синхронизации он должен появиться на другом.

Если видите «Нет доступа», проверьте, что адрес вошедшего аккаунта точно совпадает с одним из двух адресов в `firestore.rules`, а правила опубликованы.

## 4. Добавление на экран «Домой» iPhone

1. Откройте опубликованный HTTPS-адрес в Safari.
2. Нажмите системную кнопку **Поделиться**.
3. Выберите **На экран «Домой»**.
4. Подтвердите добавление.

Если вы открываете ссылку внутри Telegram, её можно использовать как Mini App/PWA-страницу во встроенном браузере. Панель Telegram («Готово», адрес и меню) отрисовывает сам Telegram — веб-страница не может заменить её собственной разметкой.

## 5. Как обновлять проект

1. Меняйте нужный файл (`index.html` — внешний вид, `app.js` — поведение, `sw.js` — кэширование).
2. Загрузите изменённые файлы в репозиторий.
3. Нажмите **Commit changes**.
4. Дождитесь обновления GitHub Pages.

При выпуске версии с изменёнными файлами откройте `sw.js` и увеличьте номер в строке:

```js
const CACHE_NAME = "nika-nastya-expenses-v3";
```

Например, на `nika-nastya-expenses-v4`. Это заставит Service Worker создать новый кэш и удалить старый. Скрипт приложения также загружается по сети с резервом из кэша, поэтому изменения логики быстрее доходят до устройств. После обновления на телефоне перезагрузите страницу, если старая версия ещё отображается.

## 6. Важные особенности данных

- Локальные данные хранятся в `localStorage` браузера и могут быть удалены при очистке данных сайта.
- Firebase-режим хранит общие расходы в Firestore по пути `groups/shared/expenses`, а время последнего закрытого расчёта — в `groups/shared/meta/state`.
- Ника и Настя используют одну общую группу `shared`; правила ограничивают доступ двумя заранее добавленными адресами.
- Вкладка «Расчёты» считает текущий период после последнего нажатия «Рассчитались». Старые расходы остаются в истории и не входят в новый период.
- Сумма перевода — половина разницы между расходами двух человек. Например, если Ника оплатила 2 360 ₽, а Настя 1 115 ₽, Настя должна Нике 622,50 ₽.
- Service Worker кэширует оболочку приложения, но не превращает Firestore в автономную облачную базу. Для записи в общую базу нужен интернет.

## 7. Если что-то не работает

| Проблема | Что проверить |
|---|---|
| Страница 404 | `index.html` лежит в корне; Pages настроен на `main` и `/ (root)` |
| Старая версия интерфейса | Увеличен `CACHE_NAME` в `sw.js`; затем перезагрузить страницу |
| Кнопка «Подключиться» выключена | Заполнены `apiKey`, `projectId`, `appId` в `app.js` |
| Firebase не загружается | Проверить `projectId`, `authDomain`, интернет и включённый Email/Password |
| `permission-denied` | Проверить два email в `firestore.rules` и нажать Publish |
| Данные есть только на одном телефоне | На обоих устройствах выполнен вход в разные разрешённые аккаунты, а статус показывает «Синхронизировано» |

## 8. Приватность

Репозиторий GitHub Pages публичен: любой может посмотреть HTML и JavaScript. Поэтому в проекте нет приватных данных и паролей. Не добавляйте в код реальные расходы, номера карт, пароли или другую конфиденциальную информацию. Данные расходов находятся в Firestore и защищаются правилами доступа.
